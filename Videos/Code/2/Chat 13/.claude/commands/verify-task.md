# /verify-task $ARGUMENTS

تحقّق رياضي من اكتمال المهمة `$ARGUMENTS` بناءً على Audit.

## الخطوات

1. **اقرأ** `PlantCare_Pre_Release_Audit.md` وابحث عن قسم المهمة `$ARGUMENTS` (مثلاً ابحث عن "A1 🔴" أو "B2 🟠").

2. **استخرج كل أوامر التحقّق** من قسم "معايير القبول" للمهمة. الأمثلة:
   - أوامر grep
   - فحوص ملفات (`ls`, `cat`)
   - أوامر بناء (`./gradlew ...`)

3. **شغّل كل أمر** وانسخ الناتج كاملاً.

4. **قرّر:**
   - ✅ كل المعايير مرّت ⇒ المهمة مكتملة. أعطِ تأكيداً مفصَّلاً.
   - ❌ معيار واحد على الأقل فشل ⇒ المهمة **ليست** مكتملة. حدّد بدقة ما الناقص.

5. **قارن مع PROGRESS.md:**
   - إذا كانت المهمة مذكورة كـCompleted في PROGRESS لكنّ التحقّق فشل ⇒ هذا regression أو ادّعاء كاذب. **اكتب تنبيه واضح للمستخدم** واقترح نقلها إلى `## Re-opened:`.
   - إذا لم تكن في PROGRESS ⇒ سجّلها أوّل مرّة باستخدام صيغة CLAUDE.md القسم 5.

## مثال للناتج المتوقّع

```
المهمة: A1 — Unify SecurePrefsHelper email read/write
معايير القبول:

[✅] grep -rn '"current_user_email"' app/src/main/java
   ⇒ نتائج فقط في SecurePrefsHelper.kt و EmailContext.kt
[✅] PlantReminderWorker يجد البريد بعد أمر adb install -r (يدوي — معلَّم بناءً على إفادة Fady)
[❌] اختبار يدوي: تثبيت v0.1 → ترقية → النبات والتذكير سليمان
   ⇒ لم يُجرَ بعد

النتيجة: 2 من 3 مرّت. المهمة شبه مكتملة — تحتاج اختبار يدوي للترقية.
```

لا تتسامح. لا تُجمِّل. ادّعِ ما يدعمه الـgrep فقط.
