## التفاصيل التقنية لكل إصلاح

### الإصلاح #1 — AddPlant dialog

**الملف:** `app/src/main/res/layout/dialog_add_to_my_plants.xml`

**Root cause:** الـ `MaterialCardView` كان يلفّ `LinearLayout` مباشرة بـ `wrap_content`. عند وجود محتوى أطول من viewport، الـ LinearLayout يمتدّ خارج حدود الشاشة، والزرّ `buttonNext` (Weiter) يقع خارج الشاشة. لا scroll layer ⇒ المستخدم لا يستطيع سحب الشاشة لإظهار الزرّ.

**التعديل:** لُفّ الـ LinearLayout بـ `ScrollView` مع `fillViewport="true"`:

```xml
<com.google.android.material.card.MaterialCardView ...>
    <!-- 2026-05-19 fix: ScrollView wrapper -->
    <ScrollView
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:fillViewport="true"
        android:scrollbars="vertical">
        <LinearLayout ...>
            ... (المحتوى الأصلي)
        </LinearLayout>
    </ScrollView>
</com.google.android.material.card.MaterialCardView>
```

**التحقّق:** `xmllint --noout dialog_add_to_my_plants.xml` ✅

### الإصلاح #2 — DSGVO consent dialog

**الملف:** `app/src/main/java/com/example/plantcare/ui/disease/DiseaseDiagnosisActivity.kt`

**Root cause:** السطر 310 كان يستخدم `AlertDialog.Builder(this)` العادي (من `androidx.appcompat.app.AlertDialog`). هذا الـ Builder لا يقرأ `materialAlertDialogTheme` attribute من theme، فيستخدم Material default — outline-only، transparent background، لا يطابق PlantCare design tokens.

**التعديل:** إضافة import + استبدال `AlertDialog.Builder` بـ `MaterialAlertDialogBuilder`:

```kotlin
import com.google.android.material.dialog.MaterialAlertDialogBuilder

// قبل: AlertDialog.Builder(this)
// بعد:
MaterialAlertDialogBuilder(this)
    .setTitle(R.string.disease_consent_title)
    .setView(msgView)
    .setPositiveButton(...) { ... }
    .setNegativeButton(...) { ... }
    .show()
```

`MaterialAlertDialogBuilder` يأخذ تلقائياً نمط `PlantCare.MaterialAlertDialog` المعرَّف في `themes.xml:35` (`materialAlertDialogTheme`) → خلفية pc_surface، فونت Inter، أزرار بـ pc_primary، corners 28dp.

**التحقّق:** الـ import موجود في السطر 39، الـ Builder مستخدم في 3 مواضع.

### الإصلاح #3 — Vergleichsbilder fallback

**الملف:** `app/src/main/java/com/example/plantcare/ui/disease/DiseaseCandidateAdapter.kt`

**Root cause:** عند `images.isEmpty()`، الكود كان:
1. يُبقي `refsLabel` ("Vergleichsbilder") ظاهراً.
2. يعرض `refsEmpty` ("Keine Referenzbilder verfügbar") كرسالة سلبية.

السبب: Gemini يعطي disease keys غير قياسية (مثل `oedem`، `wassereinlagerungen`) لا تطابق قواعد PlantVillage (38 صنف بأسماء إنجليزية) أو Wikimedia article titles. هذه حالة متوقّعة وليست خطأ.

**التعديل:** نقل `refsLabel.visibility = View.VISIBLE` من قبل الـ `when` إلى داخل كل branch، وفي branch `images.isEmpty()` جعله `View.GONE` مع إخفاء `refsEmpty` أيضاً:

```kotlin
// قبل:
holder.refsLabel.visibility = View.VISIBLE
when {
    images.isEmpty() -> {
        holder.refsEmpty.visibility = View.VISIBLE
    }
}

// بعد:
when {
    images == null -> {
        holder.refsLabel.visibility = View.VISIBLE  // loading
        holder.refsProgress.visibility = View.VISIBLE
    }
    images.isEmpty() -> {
        // 2026-05-19 fix #3: hide entire section
        holder.refsLabel.visibility = View.GONE
        holder.refsEmpty.visibility = View.GONE
    }
    else -> {
        holder.refsLabel.visibility = View.VISIBLE
        holder.refsRecycler.visibility = View.VISIBLE
    }
}
```

**التحقّق:** marker `fix #3` موجود في السطر ~200.

### الإصلاح #4 — ActionListDialogFragment system bar padding

**الملف:** `app/src/main/java/com/example/plantcare/ui/util/ActionListDialogFragment.kt`

**Root cause:** الـ Dialog يستخدم `bg_dialog_modern` مع padding 24dp ثابت. على الأجهزة بـ gesture navigation أو 3-button nav، الـ zerf "Abbrechen" يلتصق بحافة الشاشة لأن الـ Dialog لا يحاسب system bars insets ديناميكياً.

**التعديل:** إضافة `OnApplyWindowInsetsListener` في `onStart()` يحاسب bottom inset (system bars + display cutout) ويضيفه إلى الـ padding:

```kotlin
val rootView = dialog.findViewById<android.view.View>(R.id.rootActionList)
if (rootView != null) {
    val basePadPx = (24 * resources.displayMetrics.density).toInt()
    val extraPadPx = (16 * resources.displayMetrics.density).toInt()
    ViewCompat.setOnApplyWindowInsetsListener(rootView) { v, insets ->
        val bottomInset = insets.getInsets(
            WindowInsetsCompat.Type.systemBars() or
            WindowInsetsCompat.Type.displayCutout()
        ).bottom
        v.setPadding(
            v.paddingLeft, v.paddingTop, v.paddingRight,
            basePadPx + bottomInset + extraPadPx
        )
        insets
    }
    ViewCompat.requestApplyInsets(rootView)
}
```

**التحقّق:** marker `fix #4` موجود في `onStart()`.

### الإصلاح #5 — MainScreenCompose plant overlap

**الملف:** `app/src/main/java/com/example/plantcare/weekbar/MainScreenCompose.kt`

**Root cause:** الـ Box الرئيسي يحوي:
1. `Column` (المحتوى: WeekBar + Pill + Weather + RemindersList + PhotoGrid + `Spacer(weight=1f)`).
2. `BottomActionsBar` بـ `Modifier.align(Alignment.BottomCenter).zIndex(3f)` — يطفو فوق Column.

عند إضافة 4+ نباتات، الـ Column يتمدّد خارج الشاشة، آخر plant card يختفي خلف الـ BottomActionsBar لأنّ:
- الـ Column ليس scrollable.
- لا padding bottom يحاسب ارتفاع الـ BottomActionsBar.

**التعديل (3 جزئيات):**

1. إضافة imports:
```kotlin
import androidx.compose.foundation.rememberScrollState
import androidx.compose.foundation.verticalScroll
```

2. تحويل الـ Column لـ scrollable:
```kotlin
Column(
    Modifier
        .fillMaxSize()
        .background(bgColor)
        .zIndex(0f)
        // 2026-05-19 fix #5: scrollable Column
        .verticalScroll(rememberScrollState())
) { ... }
```

3. استبدال `Spacer(Modifier.weight(1f))` بـ `Spacer(Modifier.height(96.dp))`:
```kotlin
// قبل: Spacer(modifier = Modifier.weight(1f)) — لا يعمل في scrollable Column
// بعد: buffer ثابت ليبقى آخر plant card مرئياً
Spacer(modifier = Modifier.height(96.dp))
```

`96dp` = ارتفاع BottomActionsBar (~56dp) + padding (16dp×2) + safe margin (8dp).

**التحقّق:** marker `fix #5` موجود مرّتين (Column + Spacer).

### الإصلاح #6 — Archive photos custom dialog

**الملفان:**
- `app/src/main/res/layout/dialog_archive_photos.xml` (إعادة كتابة كاملة، 14 → 80 سطر)
- `app/src/main/java/com/example/plantcare/ArchivePhotosDialogFragment.java` (`onCreateDialog` + `onStart`)

**Root cause:** الـ XML الأصلي كان فقط `ScrollView + GridLayout`، يُعرَض عبر `AlertDialog.Builder(...).setTitle(...).setPositiveButton(...)`. الـ AlertDialog يستخدم Material default → title bar غير منسّق + زر "OK" بحجم صغير + خلفية شفّافة لا تطابق التطبيق.

**التعديل:**

**dialog_archive_photos.xml** الجديد يطابق `dialog_plant_detail.xml`:
- root `LinearLayout` بـ `@drawable/bg_dialog_modern`
- header: TextView centered (`@style/TextAppearance.PlantCare.Headline`) + close icon X (ImageButton ic_close)
- divider بـ `@color/pc_outlineVariant`
- ScrollView + GridLayout (المحتوى الأصلي)
- زرّ "Schließen" `@style/PlantCare.Button.Filled` في الأسفل

**ArchivePhotosDialogFragment.java**:
```java
// قبل: AlertDialog.Builder(requireContext()).setTitle(...).setView(view).setPositiveButton(android.R.string.ok, null).create();

// بعد:
TextView titleView = view.findViewById(R.id.archiveTitle);
titleView.setText(getString(R.string.archive_title_format, titleName));
view.findViewById(R.id.archiveClose).setOnClickListener(v -> dismiss());
view.findViewById(R.id.buttonArchiveClose).setOnClickListener(v -> dismiss());
android.app.Dialog dialog = new android.app.Dialog(requireContext());
dialog.setContentView(view);
return dialog;
```

`onStart()` يضع:
- عرض 92% من الشاشة (يطابق ActionListDialog و باقي modals).
- خلفية شفّافة (الـ `bg_dialog_modern` يحدّد الإطار).
- `OnApplyWindowInsetsListener` للـ bottom padding (مثل fix #4).

**التحقّق:**
- `xmllint --noout dialog_archive_photos.xml` ✅
- `rootArchivePhotos` ID مستخدم في الـ Java.
